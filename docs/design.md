# 設計メモ

縦スクロールシューティングを pygame で作る。
学習しながら作るので、この設計は「たたき台」。作りながら見直していく。

## 1. 仕様（何を作るか）

| 項目 | 内容 |
|---|---|
| 画面 | 縦長 600×800 |
| 自機 | 矢印キーで移動、スペースで弾を撃つ |
| 敵 | 上から出てきて下に進む。弾が当たると消えてスコア加算 |
| 終了条件 | 敵にぶつかったらゲームオーバー。R キーで最初からやり直す |
| 見た目 | 最初は色付きの四角。画像は後で差し替える |

## 2. ゲームループ

1秒に60回、次を繰り返す。**更新と描画は分ける。**

```
while 実行中:
    dt = 前フレームからの経過秒数
    1. 入力を受け取る   (handle_events)  … 終了は Game、それ以外は今の場面へ
    2. 状態を更新する   (scene.update)   … 移動・当たり判定・スコア
    3. 画面に描く       (scene.draw)     … 背景 → キャラ → UI
    4. 画面に出す       (flip)           … Game が 1 回だけ
```

中身（2・3）は今の場面（シーン）に任せる。Game は今どの場面かを知らない。

## 3. ファイル構成とクラス

```
src/shooter/
├─ __init__.py   … 入口。Game を作って run() するだけ
├─ settings.py   … 定数（数字）置き場
├─ game.py       … Game：ゲームループと全体の管理（監督）
├─ scenes.py     … Scene / PlayScene / GameOverScene：場面
├─ player.py     … Player：自機
├─ bullet.py     … Bullet：弾
└─ enemy.py      … Enemy：敵
```

- Player / Bullet / Enemy は `pygame.sprite.Sprite` を継承し、
  `__init__`（image と rect を用意）と `update(dt)`（自分で動く）を持つ
- PlayScene は全員に `update(dt)` を呼び、全員を描くだけ。キャラの動き方は知らない

### シーン（場面）

画面の種類ごとに、入力・更新・描画のルールをクラスにまとめる。
劇場（Game）と演目（Scene）の関係。劇場は今の演目に「入力を渡して・進めて・描かせる」だけ。

| 担当 | 持つもの |
|---|---|
| Game | 画面・時計・ゲームループ・終了（QUIT / ESC）・`flip`・今の場面 `scene`・`change_scene()` |
| 各場面 | その場面で使うデータ（自機・グループ・スコア・フォントなど） |

親クラス `Scene` は、場面が必ず持つ 3 つのメソッドを決める。中身は全部「何もしない」。
子クラスで書かなかったメソッドは、親の「何もしない」が使われる。

| メソッド | 役目 |
|---|---|
| `handle_event(event)` | イベントを 1 つ受け取る |
| `update(dt)` | 1 フレームぶん進める |
| `draw(screen)` | 描く（`flip` はしない） |

| 場面 | 何をする | 次の場面へ |
|---|---|---|
| `PlayScene` | 遊ぶ。スペースで撃つ | 敵にぶつかる → `GameOverScene` |
| `GameOverScene` | 止まった遊ぶ画面の上に GAME OVER。`update` は書かない（止まる） | R キー → 新しい `PlayScene` |

```
PlayScene ──（敵にぶつかる）──▶ GameOverScene ──（R）──▶ 新しい PlayScene
```

- 場面を切りかえるのは、その場面自身（いつ終わるかを一番よく知っているから）
- リトライは新しい `PlayScene` を作るだけ。`__init__` で全部が最初の状態になるので、`reset()` はいらない
- `GameOverScene` は止まった `PlayScene` を覚えておき、その `draw` を呼んでから GAME OVER を重ねる
- `flip` は Game で 1 回だけ。場面の `draw` に書くと、重ねて描く途中の画面が見えてチカチカする
- 3 つのクラスは `scenes.py` 1 つにまとめる。お互いを使うので、ファイルを分けると循環 import になる

### キャラの管理（Sprite Group）

グループは `PlayScene` が持つ。

| グループ | 用途 |
|---|---|
| `all_sprites` | 全キャラ。まとめて update・描画する |
| `bullets` | 弾だけ。当たり判定用 |
| `enemies` | 敵だけ。当たり判定用 |

## 4. ルール

- 数字は `settings.py` にだけ書く（コードに直接書かない）
- 移動は「1秒あたりの速さ × dt」で計算する（PCの性能で速さが変わらないように）
  - `dt = clock.tick(FPS) / 1000`
- キャラは自分の動きだけを担当し、他のキャラのことは知らない
- キャラ同士の関係（当たり判定・スコア）は PlayScene が担当する
- 画面の種類ごとの違いは `if` で分けずに、シーンのクラスで分ける

## 5. 作る順番

1. ウィンドウを出して、自機を動かす
2. 弾を撃てるようにする
3. 敵を出す
4. 当たり判定とスコア
5. ゲームオーバーとリトライ（ここでシーン管理を導入）

## 6. 後で決めること

- 敵の出現パターン・速さ・数
- 弾の連射間隔
- スコアの点数
- 画像・音
- タイトル画面（作るなら `TitleScene` を足す）
- ゲームオーバー画面の見た目（今は GAME OVER の文字だけ。最終スコアや「R でリトライ」の案内を出すか）
